# SoundLab — 사운드 디자인 6개월 커리큘럼 + 훈련 앱

커리큘럼을 읽는 것과 하는 것 사이의 거리를 없애려고 만든 앱입니다.
과제를 열면 방법이 있고, 방법 끝에 "지금 여기서 하기" 버튼이 있습니다.

---

## 1. 역할 분담

| | 담당 |
|---|---|
| HTML 문서 | 전체 지도. 일정 조망, 공유, 인쇄 |
| **SoundLab 앱** | 실제 훈련. 귀 훈련, 신스 실험, 채집, 기록 |
| DAW (3단계~) | 실무 작업. 앱이 하지 않는 영역 |

앱은 **0~2단계**를 담당합니다. 3단계부터는 의도적으로 앱 밖으로 내보냅니다.
편집·믹싱을 앱 안에서 흉내 내면 DAW로 넘어가는 시점만 늦어집니다.

---

## 2. 설치

`SoundLab.xcodeproj`를 열고 실행(⌘R)하면 됩니다.

- 프로젝트는 [XcodeGen](https://github.com/yonaskolb/XcodeGen)의 `project.yml`로 생성합니다. 파일을 추가·삭제했으면 `xcodegen generate`로 다시 만드세요.
- Deployment Target **iOS 17.0** (SwiftData, `@Observable` 사용), 마이크 권한 문구는 `project.yml`의 `info`에 들어 있습니다.
- 실기기에서 실행하려면 Signing & Capabilities에서 Team을 선택하세요. 시뮬레이터는 오디오 레이턴시와 저역 재생이 부정확합니다.

의존성은 없습니다. AVFoundation, SwiftUI, SwiftData만 씁니다.

### 파일 구조

SoundLab/

## 3. 과제와 앱 화면 매핑

### 0단계 · 귀 만들기 (W1–4)

| 과제 | 앱에서 | 완료 기준 |
|---|---|---|
| 매일 15분 대역 식별 | 귀 훈련 탭 | 28일 중 24일 기록 |
| 다섯 대역 눈 감고 구분 | 귀 훈련 · 중급 5밴드 | 80% 3세션 연속 |
| 레퍼런스 20개 분석 | 기록 → 레퍼런스 노트 | 20개 등록 |

**귀 훈련이 실제로 하는 일**
핑크 노이즈를 실시간 생성해 `AVAudioUnitEQ` 파라메트릭 밴드 하나를 걸고, A/B로 원본과 비교하게 합니다. 밴드폭은 0.5옥타브로 좁게 잡았습니다. 넓으면 너무 쉬워서 훈련이 안 됩니다.

난이도는 세 단계이고 두 축이 동시에 어려워집니다 — 밴드 수(3→5→8)와 게인(±12→±6→±3dB). 입문에서는 부스트만 나오고, 중급부터 컷이 섞입니다.

틀린 대역은 세션 결과에 모입니다. 3kHz가 가장 오래 걸립니다.

### 1단계 · 신시사이스 (W5–10)

| 과제 | 앱에서 | 완료 기준 |
|---|---|---|
| 파라미터 하나씩 극단까지 | 신스 랩 · 집중 모드 | 12개 전부 한 바퀴 |
| 재현 과제 6개 | 신스 랩 · 과제 선택 | 6개 통과 + 레시피 메모 |
| Vital로 옮겨 타기 | (앱 밖) | 프리셋 6개 저장 |

**집중 모드가 핵심입니다.** 파라미터 하나를 선택하면 나머지 슬라이더가 잠깁니다. Minimoog에서 막혔던 지점이 여기입니다 — 여러 노브를 동시에 만지면 무엇이 무엇을 바꿨는지 영영 알 수 없습니다. 소프트웨어니까 그 규율을 강제할 수 있습니다.

**재현 과제 6개**는 목표 패치가 코드에 들어 있어서, 목표 소리를 듣고 → 직접 만들고 → A/B로 비교할 수 있습니다. 근접도 퍼센트가 나오지만 참고용입니다. 힌트는 최소 10분 직접 해본 뒤에 여세요.

과제 설계 의도:

- **킥**과 **레이저**는 같은 하강 피치 스윕인데 전혀 다르게 들립니다. 파형과 피치 대역의 차이입니다.
- **물방울**은 킥의 정반대(상승 스윕)입니다. 물방울은 떨어지는데 소리는 올라간다 — 물리와 지각이 어긋나는 사례입니다.
- **심벌**은 오실레이터를 아예 쓰지 않습니다. 필터 모드가 음색을 결정한다는 걸 몸으로 알게 하는 과제입니다.
- **바람**은 유일한 지속음입니다. 타악기적 사고에서 빠져나오게 합니다.
- **심장박동**은 180Hz 아래에서 작동합니다. 크게 들리는 소리가 아니라 몸에 닿는 대역이 감정을 만든다는 것.

신스 자체는 감산 합성 최소 구성입니다 — 오실레이터 4종 + 핑크 노이즈, Chamberlin SVF(로우/밴드/하이패스), 피치 스윕 엔벨로프, 필터 엔벨로프, ADSR.

### 2단계 · 녹음과 폴리 (W11–14)

| 과제 | 앱에서 | 완료 기준 |
|---|---|---|
| 집 안 물건 30개 | 기록 → 필드 레코딩 | 30개, 재배치 아이디어 포함 |
| 바이올린을 소재로 | 기록 → 필드 레코딩 | 8개 이상 |
| 노이즈 플로어 정리 | 기록 → 주간 결과물 | 체크리스트 저장 |

녹음마다 **무엇을 녹음했나**와 **무엇으로 쓸 수 있나**를 따로 적게 되어 있습니다. 두 칸이 분리된 것이 이 과제의 전부입니다. 소리의 출처와 의미를 분리하는 훈련.

정식 녹음은 홈 레코딩 셋업에서 하세요. 앱은 아이디어를 놓치지 않기 위한 도구입니다.

### 3단계 · 편집과 프로세싱 (W15–20)

앱은 커리큘럼 내용과 완료 기준만 보여줍니다. 작업은 Reaper 또는 Logic에서 합니다.

## 4. 주간 루틴

- **매일 15분** — 귀 훈련 탭. 빠지지 않는 것이 전부입니다
- **주 4~6시간** — 현재 단계 작업
- **주 1개** — 완성된 결과물. 미완성은 세지 않습니다
- **일요일 30분** — 기록 → 주간 결과물에 "소리가 왜 그 감정을 만들었는지" 한 단락

26주 × 1개 = 결과물 26개. 6개월 뒤 남는 건 이것뿐입니다.

---

## 5. 앱이 일부러 하지 않는 것

- **믹싱·마스터링** — DAW가 훨씬 잘합니다. 여기서 흉내 내면 이행만 늦어집니다
- **샘플 라이브러리 제공** — 직접 녹음하는 것이 2단계의 과제 자체입니다
- **자동 채점** — 근접도는 참고 수치입니다. 판단은 귀로 합니다
- **알림** — 하루 15분을 알림이 만들어 주지는 않습니다. 필요하면 직접 붙이세요

## 6. 이 앱 자체가 3번 포트폴리오의 출발점입니다

`MiniSynth.swift`는 이미 동작하는 실시간 합성 코드입니다. 파일 재생이 아니라 파라미터로 소리를 만듭니다.

포트폴리오 3번(절차적 사운드)은 이 파일을 다른 앱으로 옮기는 것에서 시작합니다. 앱 상태 — 스크롤 속도, 남은 시간, 연속 성공 횟수 — 를 `Patch`의 필드에 매핑하면 됩니다. 예를 들어 연속 성공 횟수를 `pitch`에, 남은 시간을 `cutoff`에.

`Patch`를 `Codable`로 만들고 프리셋을 저장할 수 있게 하면, 5번(사운드팩 판매)의 제작 도구로도 쓸 수 있습니다.

## 7. 알려진 한계

- 오실레이터가 naive 파형이라 고음역에서 에일리어싱이 있습니다. 학습용으로는 문제없지만 제품 사운드에는 쓰지 마세요
- 렌더 스레드 파라미터 갱신에 락이 없습니다. 슬라이더를 빠르게 움직이면 아주 드물게 지직거릴 수 있습니다. 의도한 트레이드오프입니다 — 오디오 스레드에서 락을 잡는 쪽이 더 나쁩니다
- 시뮬레이터에서는 심장박동 과제의 저역이 거의 들리지 않습니다
- Xcode 26.2 · iOS 시뮬레이터에서 빌드·실행을 확인했습니다. 실기기 오디오 동작은 아직 확인하지 않았습니다
